# Recall Watch MCP server

An MCP server with one tool, `supplier_history`. It returns one firm's FDA record in a single answer:

- **Warning letters** addressed to the firm, with FDA's subject line, the issuing office and a link to the letter on fda.gov.
- **Form 483 inspection citations**, grouped by the regulation cited and counted by inspection. This source needs FDA Data Dashboard credentials (see below).
- **Recalls** by the firm since 2012 (food, which includes supplements, drug and device), with the class, status, product, reason and a link to FDA's enforcement report.

It answers one question: "what has FDA said about this contract manufacturer?" Brands ask it before they sign a co-packer.

**Source.** The public repository, [github.com/moshejs/recall-watch-mcp](https://github.com/moshejs/recall-watch-mcp), is generated by a script from a private source repository (the Recall Watch site), and holds only this server and the site code it uses. Changes are made in the private repository and copied here, so pull requests can't be merged directly; [open an issue](https://github.com/moshejs/recall-watch-mcp/issues) instead.

It speaks MCP over stdio (newline-delimited JSON-RPC 2.0), has no dependencies and needs Node 22 or later. It uses the same code as the site's `/supplier` page (`lib/supplierHistory.js`), so the same rules apply:

- Only FDA's own fields are returned, each with its FDA link.
- Matching is by company name only, and the answer says so.
- A source that failed or isn't configured comes back as `NOT CHECKED` or `NOT CONNECTED` with the reason, never as zero.
- Warning letters go through the site's FDA client: an honest User-Agent naming the site, a 30-minute cache and a 15-minute pause after fda.gov refuses.

## Install and use

> The npm package `recall-watch-mcp` is prepared but **not published yet**. Until it is, use "Run from a clone" below.

Add it to your MCP client's configuration. Claude Desktop keeps it in `claude_desktop_config.json` (macOS: `~/Library/Application Support/Claude/`, Windows: `%APPDATA%\Claude\`, Linux: `~/.config/Claude/`); Cursor, Windsurf and most other clients take the same `mcpServers` shape:

```json
{
  "mcpServers": {
    "recall-watch": {
      "command": "npx",
      "args": ["-y", "recall-watch-mcp"],
      "env": {
        "OPENFDA_API_KEY": ""
      }
    }
  }
}
```

Claude Code: `claude mcp add recall-watch -- npx -y recall-watch-mcp`

Docker (stdio, so `-i`): from a clone of the public repository, `docker build -t recall-watch-mcp .`, then `docker run -i --rm -e OPENFDA_API_KEY recall-watch-mcp`.

**Tool.** `supplier_history(firm, max_items?)`: one firm's FDA warning letters, Form 483 citations and recalls since 2012, each with its FDA link. `firm` is the company name (2 to 80 characters, required); `max_items` (1 to 50, default 10) caps how many records the text lists. Details under "The tool" below.

**Environment variables.** All optional; see the table under "Run from a clone". `OPENFDA_API_KEY` lifts openFDA's keyless limit; `FDA_DASHBOARD_USER` and `FDA_DASHBOARD_KEY` together turn on Form 483 citations. The FDA hosts below are fixed in the code: no variable can point the requests, or your keys, anywhere else.

**What leaves your machine, and to where.** Each lookup sends the firm name you ask about, and nothing else about you, to:

| Destination | What is sent | Why |
|---|---|---|
| `api.fda.gov` (openFDA) | The cleaned firm name, 3 requests (food, drug, device recalls), plus `OPENFDA_API_KEY` as a URL parameter if set | Recalls |
| `www.fda.gov` | The cleaned firm name in a full-text search of FDA's warning-letter listing, 1 request | Warning letters |
| `api-datadashboard.fda.gov` | The cleaned firm name and your `FDA_DASHBOARD_USER` / `FDA_DASHBOARD_KEY` as request headers, 1 request, only when both are set | Form 483 citations |

Every request carries the User-Agent `RecallWatch/1.1 (+<CONTACT_URL>; FDA public-records search)`. Nothing is sent to the Recall Watch site or to its author: the links in each answer point at the site, but the server does not call it. Nothing is written to disk; answers are cached in memory only (openFDA 10 minutes, warning letters 30 minutes with a saved copy for up to 7 days while the process runs, citations 6 hours) and vanish when the process exits.

**Limits.** Name matching only; FDA's warning-letter feed is undocumented and sits behind bot protection, so letters can come back `NOT CHECKED`; openFDA allows 240 requests a minute and 1,000 a day per IP without a key, and 240 a minute and 120,000 a day per key with one (open.fda.gov/apis/authentication, read 2026-11-22), and each lookup makes 3; each outbound request times out after 20 seconds. More under "Limits" below.

**Untrusted text.** Firm names, subject lines, product descriptions and recall reasons are FDA's text, returned as written. Treat them as data, not instructions.

**Report a problem.** [Open an issue](https://github.com/moshejs/recall-watch-mcp/issues) with the firm name you looked up and the time of the lookup.

## Run from a clone

From the root of a clone (no install step; there are no dependencies):

```bash
node mcp/server.js
```

Client configuration (Claude Desktop, Claude Code, Cursor and others use this shape):

```json
{
  "mcpServers": {
    "recall-watch": {
      "command": "node",
      "args": ["/absolute/path/to/your/clone/mcp/server.js"],
      "env": {
        "OPENFDA_API_KEY": "",
        "FDA_DASHBOARD_USER": "",
        "FDA_DASHBOARD_KEY": ""
      }
    }
  }
}
```

With Claude Code: `claude mcp add recall-watch -- node /absolute/path/to/your/clone/mcp/server.js`.

All variables are optional:

| Variable | Effect |
|---|---|
| `OPENFDA_API_KEY` | Free [openFDA key](https://open.fda.gov/apis/authentication/). Without one, openFDA allows 1,000 requests a day per IP; each lookup makes 3. |
| `FDA_DASHBOARD_USER` + `FDA_DASHBOARD_KEY` | FDA Data Dashboard API credentials, which turn on Form 483 citations. Request them through FDA's OII Unified Logon ([API docs](https://datadashboard.fda.gov/oii/api/index.htm)). Without them, citations come back as `NOT CONNECTED`. |
| `CONTACT_URL` | The URL named in the User-Agent sent to FDA. |
| `SITE_URL` | Base for the links back to the site (default `https://recall-watch.quentin.software`). |

## The tool

`supplier_history`

| Argument | Type | |
|---|---|---|
| `firm` | string, 2–80 characters, required | The company name. The legal name of the manufacturing firm works best, for example `Nutratech, LLC`. |
| `max_items` | integer 1–50, default 10 | How many letters, citation themes and recalls to list. Counts always cover everything found. |

The tool returns:

- `content`: plain text an assistant can quote, with one line per record and FDA's link on each.
- `structuredContent`: the same data as JSON. It has `letters`, `citations` and `recalls`, each with a `status` (`checked`, `partial`, `not_checked` or `not_configured`) and an `error` that explains anything other than `checked`. It also has `page`, a link to the full `/supplier` page, and `watchUrl`, where the firm can be watched for new letters and recalls.

The tool is read-only (`readOnlyHint`) and reaches the open web (`openWorldHint`). Bad input, such as a name under 2 characters, comes back as a tool result with `isError: true`, so the model can correct it.

An example answer for `Nutratech, LLC` (live, 2026-11-12, without Data Dashboard credentials):

```
WARNING LETTERS (checked): 1 addressed to a matching firm
- 2026-06-04 | Nutratech, LLC | FDA subject: CGMP/Dietary Supplement/Adulterated/Misbranded | issued by Human Foods Program | https://www.fda.gov/inspections-compliance-enforcement-and-criminal-investigations/warning-letters/nutratech-llc-723021-06042026

FORM 483 INSPECTION CITATIONS (NOT CONNECTED): Inspection citations need FDA Data Dashboard API credentials, ...

RECALLS (checked): 0 by a matching firm since 2012 (Class I 0, Class II 0, Class III 0)
```

## Protocol

The server implements `initialize`, `ping`, `tools/list` and `tools/call`, and ignores notifications. It answers with the client's protocol version when it supports it (2025-11-25, 2025-06-18, 2025-03-26 or 2024-11-05), and with 2025-11-25 otherwise. Only JSON-RPC goes to stdout; logs go to stderr. The tests are in `test/mcp.test.js` (run them with `node --test test/mcp.test.js`; they make no network calls) and include a real stdio round trip.

## Limits

- Name matching only. No FDA source shares an identifier with the others, so similar names can be different firms. Check the address and the FDA record.
- Warning letters come from an undocumented FDA feed behind bot protection; if fda.gov refuses, letters come back `NOT CHECKED`. The newest 100 letters mentioning the name are checked.
- Form 483 data leaves out hand-written 483s, state contract inspections and inspections whose classification isn't final.
- openFDA recall data runs from 2012 and openFDA calls it unvalidated. USDA meat and poultry recalls aren't included.
- Not legal advice and not a consumer report.
